# Plan for #6: Add run status transitions

## Goal
Add `PATCH /api/runs/:id/status` so runs can move from `planned` to `running` to `done`. Invalid transitions return 409 with the current and requested statuses, and unknown runs return the existing 404 shape.

## Dependencies
- confirmed: `src/runs.ts::RunStore` stores mutable run status; change: yes
- confirmed: `src/app.ts::createApp` owns run routes and error responses; change: yes
- confirmed: `test/app.test.ts::runs api` covers API behavior with supertest; change: yes
- confirmed: `README.md` API table documents routes; change: yes
- confirmed: `src/config.ts`, `k8s/configmap.yaml` environment contract; change: no

## Tests
- `test/app.test.ts`: allowed planned-to-running-to-done path, invalid transition, and unknown id.

## Environment contract
No environment variables are added or changed.

## Risks
Incorrect transition checks could allow skipping or reversing states, or produce the wrong error shape. Unit, build, rollout, stability, smoke, and browser pipeline gates could fail if the API route or existing behavior regresses.

## Open questions
None.

## Decisions
Successful status updates return the updated run with HTTP 200.
